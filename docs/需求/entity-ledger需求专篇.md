## 1. 定位与边界

### 1.1 定位

```
输入：候选目标观测（来自 device-ingest 归一化事件 / 人工录入 / 融合结果）
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│  entity-ledger（C++，无 Web 框架、无 SQL）                 │
│  REG 实体登记 → ID 编号与一致性 → RATE 威胁评级 →           │
│  RANK 优先级排序 → TRK 轨迹服务 → ACT 动作状态机            │
│                      │                                   │
│                      └──► 出口：IEntitySink（宿主实现）      │
└──────────────────────┬───────────────────────────────────┘
                       │ 台账快照 + 变更事件（target.state）
                       ▼
   宿主：落库 + 广播 ｜ scoring：读优先级 ｜ view-composer：读图元
```

**一句话**：entity-ledger 回答"**这个实体是什么、有多危险、排第几、去过哪**"。
它不回答"打不打它"（`scoring` 出方案）、也不回答"它在地图上画成什么符号"（`view-composer` + `map-2d`）。

### 1.2 为什么必须是独立引擎

1. **它是唯一一处能收口编号一致性的地方**：只要台账是唯一权威、且引擎提供一致性检查，初稿 §10.12 的矛盾才有解。
2. **它有两个消费者**：换一套指挥系统，实体类型与评级口径会变，但**台账 + 编号 + 轨迹 + 动作状态机相同**。
3. **它被 `scoring` 依赖**：优先级是打击方案的输入。

### 1.3 范围边界

| 做 | 不做 |
|---|---|
| 实体登记：类型、坐标、来源、置信度、动态状态 | 🚫 不含具体**实体类型名**（机动指挥节点/防空火力阵地/通信保障节点 属规则） |
| **编号规则与一致性检查**（任务内唯一 `target_no`） | 🚫 不做打击方案与成功率（`scoring`） |
| 威胁评级引擎（打分，可复算、可解释） | 🚫 不做地理符号与配色（`view-composer` / `map-2d`） |
| 优先级排序与序列（加入攻击序列） | 🚫 不做告警产生（`alert-engine`，本引擎只发变更） |
| 轨迹服务：写入、区间查询、**裁剪与抽稀**、时间轴输出 | 🚫 不做时间轴播放控件（`map-2d` 已有 `ReplayBar`） |
| 动作状态机：持续跟踪 / 重点监视 / 升级打击 / 打击，含幂等与互斥 | 🚫 不做毁伤判定（属评估口径，见 §9 待确认） |
| 情报关联关系（节点链） | 🚫 不做自然语言分析文案（`llm-provider`） |

### 1.4 硬约束

| 约束 | 取值 | 依据 |
|---|---|---|
| 现有接口形状 | `/targets`、`/targets/{id}`、`/targets/{id}/track`、`/targets/{id}/{action}` 返回形状**不得破坏** | 契约 §3.5；`Api.cc` L712–759 |
| `target.state` 事件 | 负载含 `{targetId, targetNo, threat, confidence, dynamicState, lng, lat, status:"red"\|"yellow"\|"gray"}` | 契约 §4 |
| 动作幂等 | `upgrade` 已执行时 MUST 返回 `code=1002 正在执行/已执行`（现状行为，保留） | `Api.cc` L744 |
| 动作参数 | `action ∈ {track, strike, upgrade, watch}` | `Api.cc` L738；前端 `useStore.ts` L449 |
| 事件日志 | `target.strike` / `target.upgrade` MUST 落事件日志 | `Api.cc` L748 |
| 编号口径 | **任务内唯一 `target_no`（整数）**，跨界面强一致 | 契约 §2；初稿 §10.12 |
| 演示数据 | 场景二 T4-1 五个目标；来源含融合/雷达/光电/电子；动态状态含机动中/活跃/部署中/转移中/短暂停留 | 初稿 §8 T4-1 |
| 语言/构建 | C++17 + CMake ≥ 3.20；仅 `nlohmann/json` | 对齐既有 C++ 模块 |

## 3. 功能需求条目

### 3.1 实体登记（ELG-REG）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| ELG-REG-01 | **MUST** 实体类型由规则声明（`{ key, 名称, 基础威胁, 属性 }`），引擎 MUST NOT 内建类型名 | 换规则即换类型集；全仓检索 `机动指挥节点` 零命中 | ⏳ |
| ELG-REG-02 | **MUST** 台账字段：`{ id, targetNo, 类型, 坐标, 来源, 置信度, 动态状态, 威胁等级, 优先级, 关系链, 时间 }` | 字段完整可序列化；缺省字段有定义行为 | ⏳ |
| ELG-REG-03 | **MUST** 按任务隔离，且同一任务内 `targetNo` 唯一 | 重复 `targetNo` 登记被拒绝并给可读原因 | ⏳ |
| ELG-REG-04 | **MUST** 多源汇入去重：同一实体的多来源观测 MUST 能合并（按规则声明的主键或空间/类型相似度） | 同一目标三条来源观测 → 合并为一条且来源标注为多源 | ⏳ |
| ELG-REG-05 | **MUST** 置信度可更新：新观测到达时按规则融合（不是简单覆盖） | 融合规则可配；结果可复现 | ⏳ |
| ELG-REG-06 | **SHOULD** 动态状态机：状态迁移（如 短暂停留 → 机动中）由规则声明合法迁移 | 非法迁移被拒绝并给原因 | ⏳ |

### 3.2 编号与一致性（ELG-ID）

> 本域是**初稿 §10.12 的唯一收口点**。

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| ELG-ID-01 | **MUST** 编号规则可配：序号生成（连续 / 不复用 / 起始值）由规则声明 | 删除中间目标后新增，编号行为符合规则 | ⏳ |
| ELG-ID-02 | **MUST** 一致性检查接口：给定一组"视图"或"界面集合"，校验 `targetNo` 与类型在各视图下是否一致，输出**逐条差异报告** | 人为制造"T4-1 五个 / T7-2 七个"的场景 → 报告定位到具体编号与视图 | ⏳ |
| ELG-ID-03 | **MUST** 全集与子集语义显式：提供"某阶段应可见的目标集合"查询（避免各界面自行过滤导致数量不一致） | 同一阶段两次查询结果一致；跨阶段集合变化可解释 | ⏳ |
| ELG-ID-04 | **MUST** 类型与编号绑定校验：同一 `targetNo` 的类型 MUST NOT 在不同阶段变化（除显式的"类型重判"动作） | 制造类型漂移 → 被检出；走重判动作 → 允许并留痕 | ⏳ |
| ELG-ID-05 | **SHOULD** 高价值标记唯一性：同一任务内"高价值"标记的数量与去向可查（初稿里 002/003 之争） | 可查询高价值集合；越界时报错 | ⏳ |

### 3.3 威胁评级（ELG-RATE）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| ELG-RATE-01 | **MUST** 评级规则可注入：因子清单（类型基础威胁、距离、活动状态、防护强度、电子干扰等）、权重、分档阈值全部由规则声明 | 换规则即换评级；引擎内无 `"high"` 字面量判断 | ⏳ |
| ELG-RATE-02 | **MUST** 打分可复算：输出逐因子得分与总分，导出后可手算核对 | 任取一目标，导出项手算等于总分 | ⏳ |
| ELG-RATE-03 | **MUST** 分档由阈值决定（不是布尔判断）：`high`/`mid`/`low` 的边界可配 | 调阈值后同目标分档变化可复现 | ⏳ |
| ELG-RATE-04 | **MUST** 距离因子用真实几何：以任务参考点（或指定基准）计算距离，不得用占位值 | 给定两点坐标，距离手算一致 | ⏳ |
| ELG-RATE-05 | **MUST** 评级输入显式：为结构化快照，引擎 MUST NOT 读全局状态或数据库 | 单测只传快照即可评级 | ⏳ |
| ELG-RATE-06 | **MUST** 打击窗口由计算得出：现状硬编码字符串（`Api.cc` L728）MUST 移除；窗口 MUST 由轨迹与规则（暴露规律）推算，并输出为**结构化时间区间** | 全仓检索 `12 分 32 秒` 零命中；窗口为可计算的时间区间 | ⏳ |

### 3.4 优先级与序列（ELG-RANK）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| ELG-RANK-01 | **MUST** 排序规则可配：默认按威胁等级 + 优先级字段，次级键稳定 | 同分排序稳定可复现 | ⏳ |
| ELG-RANK-02 | **MUST** 优先级值可显式设置（初稿 T5-2：优先级 1/2/3） | 设置后排序与界面一致 | ⏳ |
| ELG-RANK-03 | **MUST** 打击序列：支持加入/移出序列，序列内唯一、可排序（"加入攻击序列"） | 重复加入幂等；移出后序号键稳定 | ⏳ |
| ELG-RANK-04 | **SHOULD** 序列变更可审计：谁在什么时候把谁加入了序列 | 可从事件日志复原序列变化 | ⏳ |

### 3.5 轨迹服务（ELG-TRK）

| 编号 | 需求描述 | 验收标准 | 状态 |
|---|---|---|---|
| ELG-TRK-01 | **MUST** 轨迹写入：按 `{targetId, ts, lng, lat, ...}` 追加，MUST 按 ts 有序 | 乱序写入后查询仍有序 | ⏳ |
| ELG-TRK-02 | **MUST** 区间查询：按 `[from, to)` 取点，支持分页/上限截断且**不静默丢** | 超限时返回截断标记与游标 | ⏳ |

| ELG-TRK-04 | **MUST** 时间轴输出：产出可直接喂给回放组件的结构（对齐 `map-2d` M2-DRAW-18 的入参形状） | 输出可被 `map-2d` 回放接口直接消费（由宿主适配） | ⏳ |
| ELG-TRK-05 | **SHOULD** 预测轨迹：按规则外推若干点并**显式标注为预测**（初稿 T6-1 "预测轨迹"虚线） | 预测点带标记，不与实测点混淆 | ⏳ |
| ELG-TRK-06 | **SHOULD** 轨迹保留：过期点清理可配（避免无界增长） | 配置后旧点被清理且计数可查 | ⏳ |

| ELG-ACT-06 | **SHOULD** 动作可撤销语义显式：可撤销/不可撤销由规则声明 | 尝试撤销不可撤销动作被拒绝 | ⏳ |

| ELG-INTEL-03 | **SHOULD** 已确认/疑似两态：支持 `confirmed` / `suspected` 标记（第三屏虚线框 + 问号） | 两态可筛选、可统计 | ⏳ |

| ELG-NFR-05 | **SHOULD** 性能：1000 实体台账下评级全量 ≤ 10 ms；轨迹区间查询（1 万点）≤ 5 ms | 实测达标 | ⏳ |

## 4. 引擎与规则的划分（policies）

| 属引擎（可复用） | 属规则（`policies/mapapp`，项目专属） |
|---|---|
| 登记、去重、置信度融合机制 | **实体类型清单**：机动指挥节点 / 防空火力阵地 / 通信保障节点 … |
| 编号生成与**一致性检查** | **编号起始值与是否复用** |
| 评级引擎（因子求值、加权、分档） | **评级因子与权重、分档阈值** |
| 排序与打击序列机制 | **默认排序偏好**、序列上限 |
| 轨迹写入/查询/抽稀/时间轴/预测框架 | **抽稀参数、预测外推规则** |
| 动作状态机与幂等 | **动作清单与前置条件**（track/watch/strike/upgrade 的语义） |
| 关系链与已确认/疑似两态 | **动态状态取值集**（机动中/活跃/部署中/转移中/短暂停留） |

**判据**：引擎公开接口里出现 `机动指挥节点`、`高价值`、`预计 12 分 32 秒`、`已开始持续跟踪` 即破线。

## 6. 风险

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | 一致性检查会**暴露现有演示数据的矛盾**（五个/六个/七个） | 演示"自证不一致" | 这正是 D2 的目的：先用检查把差异列出来，再由 `mission-baseline` 定一份权威集合；演示数据同步修正 |
| R2 | 打击窗口改为计算后，数值与截图不一致 | 界面回归 | 按演示口径配置规则，使计算结果复刻截图值；同时保留"规则可调" |
| R3 | 多源去重规则不当，把两个真目标合成一个 | 漏目标 | 去重规则必须可配且**默认保守**（宁可标多源不合并），并提供人工拆分 |
| R4 | 评级抽象过度（做成通用评分框架） | 与 `scoring` 重复、配置地狱 | 只支持"因子线性加权 + 阈值分档"，不做多目标优化 |
| R5 | 轨迹无界增长 | 存储与查询退化 | ELG-TRK-06 保留策略；实测门槛 |
| R6 | 关系链成环导致查询死循环 | 服务挂起 | ELG-INTEL-01 成环检出设为 MUST |

## 7. 验收清单

- [ ] 空环境 clone → 一条命令构建 → 一条命令跑通验收脚本（退出码 0）
- [ ] 全仓检索实体类型名、`高价值`、`12 分 32 秒`、`已开始持续跟踪` → 零命中
- [ ] 重复 `targetNo` 登记被拒绝
- [ ] 同一目标三条来源观测合并为一条，来源标为多源；默认保守不误合
- [ ] 制造"某视图多两个目标" → 一致性报告定位到具体编号与视图
- [ ] 同一阶段两次查询可见集合一致
- [ ] 制造类型漂移 → 被检出；走重判动作 → 允许并留痕
- [ ] 任取一目标导出逐因子得分，手算等于总分；调阈值后分档变化可复现
- [ ] 打击窗口为结构化时间区间，可复算
- [ ] 连点两次 upgrade，第二次得到 `code=1002`
- [ ] 动作只产结构化事件，不产自然语言
- [ ] 未满足前置条件的动作被拒绝并给原因
- [ ] 关系链成环被检出
- [ ] 轨迹乱序写入后查询有序；超限返回截断标记；抽稀带标注
- [ ] 轨迹时间轴输出可被 `map-2d` 回放接口消费（由宿主适配）
- [ ] 预测点带显式标记，不与实测点混淆
- [ ] 1000 实体评级全量 ≤ 10 ms；1 万点区间查询 ≤ 5 ms
